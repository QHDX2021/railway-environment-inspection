## 1. 产品和性能基线

| 项目 | 手册内容 | 项目含义 |
|---|---|---|
| 产品 | PandarXT，32 线中距机械式激光雷达 | 与项目原选型 XT32 对应；最终订货 SKU 仍需和设备铭牌核对 |
| 扫描方式 | 机械旋转 | 记录电机转速和扫描帧率，点云解析不能假设固态扫描 |
| 通道数 | 32 | 点云协议固定通道数字段为 32 |
| 测量距离 | 0.05～120 m | 作为能力参考，不替代现场目标和反射率测试 |
| 典型测远 | 80 m（10% 反射率，通道 9～24）；50 m（其他通道） | 受反射率、天气、温度和通道影响 |

| 垂直角分辨率 | 1° | 准确角度以随雷达角度修正文件为准 |
| 扫描帧率 | 5/10/20 Hz | 默认配置需从网页或 API 读回 |
| 回波 | 单回波；双回波：最后及最强（默认）、最后及第一、第一及最强 | 首版任务需明确回波模式，不能只记录“XT32 点云” |
| 波长/激光等级 | 905 nm；Class 1 人眼安全 | 现场作业仍按设备安全提示执行 |

手册给出的测距准度、精度和测远值是特定测试条件下的厂家参考，不直接替代铁路现场验收指标。

## 2. 供电、结构和接口

| 项目 | 手册确认值 | 项目设计要求 |
|---|---|---|
| 输入电压 | DC 9～36 V | 与整机 24 V 电池/DC-DC 方案匹配，必须测线缆末端电压 |
| 典型功耗 | 10 W（12 V、600 RPM、室温） | 仅雷达本体，不含接线盒；整机电源按峰值配置 |
| 全工况峰值 | 小于 30 W | 外部电源建议至少提供 30 W；低温启动和 20 Hz 时功耗可能高于典型值 |
| 工作温度 | -20℃～65℃ | 车载机箱热设计和温升测试的设备边界 |
| 防护等级 | IP6K7 | 机箱、连接器和安装结构不能降低整机防护 |
| 重量 | 侧面出线约 0.8 kg；底部出线约 0.9 kg | 结构减震和支架强度按实际出线版本冻结 |
| 以太网 | 百兆以太网：100BASE-TX 或车载 100BASE-T1 | 首版优先核对实际线缆/载板网口；不能按千兆设备设计交换机余量 |
| 连接器 | Lemo 9 针，型号以手册为准 | 线束和接线盒选型必须核对公母头、出线方向和弯曲半径 |

供电时序：上电前输入电压应低于 1 V 并保持至少 50 ms；开始爬升后 500 ms 内达到工作电压的 90%；下电降至 1 V 以下后至少保持 50 ms 再重启。电源线线径建议不大于 26 AWG，长线必须计算压降。

## 3. Lemo 接口和 GNSS 时间输入

### 3.1 100BASE-TX 标准接口

| 引脚 | 信号 | 电平/颜色 | 项目用途 |
|---:|---|---|---|
| 1 | GNSS PPS | 3.3～12 V，黑 | UMD982 PPS 经缓冲/分配后送入雷达 |
| 2 | GNSS DATA | -13～13 V，紫 | 接收 UMD982 NMEA，需按 RS232 电平链路设计 |
| 3 | GND | 0 V，棕 | 电源/信号地 |
| 4 | VIN | 9～36 V，白 | 雷达供电 |
| 5/6/7/8 | Ethernet TX/RX | 差分，黄/绿/粉/灰 | 百兆以太网数据 |
| 9 | 预留 | 红 | 不使用 |

### 3.2 PPS 与 NMEA 时序

- PPS 周期：1 s ± 50 μs（上升沿到上升沿）；
- PPS 脉宽：至少 1 ms，建议 10～100 ms；
- NMEA 发出时刻晚于本秒 PPS 上升沿；
- NMEA 结束时刻晚于本秒 PPS 下降沿；
- NMEA 结束时刻早于下一秒 PPS 上升沿，并且距离下一次 PPS 上升沿至少 100 ms；
- GNSS 作为时钟源时，雷达每秒输出一个 GNSS UDP 数据包；PTP 作为时钟源时，雷达不输出 GNSS 数据包。

接线盒的 GNSS 端口资料还给出：RS232 电平、9600 bps、PPS 输入 3.3～12 V、PPS 上升沿不超过 500 ns，推荐脉宽超过 1 ms。最终采用直接雷达线束还是选配接线盒，需要按采购形态核对。

## 4. 网络和默认参数

| 参数 | 手册默认/范围 | 项目建议 |
|---|---|---|
| 雷达控制 IP | 192.168.1.201 | 样机先按此地址验证；生产网段由 Linux 网络配置统一管理 |
| 主机网段 | `192.168.1.X`，X=2～200 或 202～254 | 初始主机可用 192.168.1.100/24，避免与雷达地址冲突 |
| 子网掩码 | 255.255.255.0 | 与雷达直连或专用采集网口一致 |
| VLAN | 默认关闭；可用 1～4094 | 首版先关闭 VLAN，确认拓扑后再启用 |
| 点云目的 IP | 默认 255.255.255.255 | Linux 采集时优先改为单播主机地址，避免广播扩散 |
| 点云目的端口 | 2368 | Linux 雷达适配器固定读回实际配置 |
| 点云源端口 | 10000 | 用于抓包、端口占用和防火墙配置 |
| GNSS 目的端口 | 10110 | Linux 或接收服务监听；PTP 模式不产生 GNSS 包 |
| PTC/网页/PTP | 9347 / 80 / 319、320 | 防火墙和局域网控制策略需明确放行范围 |

Linux 主机接入时必须记录雷达 IP、目的 IP、端口、VLAN、MAC、序列号和固件版本。工程调试可使用网页 `http://192.168.1.201`，生产程序不能把网页操作当作唯一控制接口。

## 5. 时间同步方案

### 5.1 项目首选：GNSS PPS + NMEA

与本项目 UMD982 双天线方案匹配：

```text
UMD982 PPS ──→ PCB STM32H750 时间捕获
          └──→ XT32 GNSS PPS
UMD982 NMEA ──→ 电平适配/接线盒 ──→ XT32 GNSS DATA
UMD982 数据 ──→ Linux GNSS 服务（原始数据、定位和定向状态）
```

PPS 分配必须经过明确的电气缓冲/扇出设计，不能把多个输入直接并接到 UMD982 输出。XT32 的 NMEA 句子可选 GPRMC、GNRMC、GPGGA；具体选择要和 UMD982 实际输出及雷达固件版本一致。手册中软件 0.1.xx 默认 GPRMC、1.0.xx 默认 GPGGA，1.0.xx 才支持 GNRMC。

项目初始建议：`Clock Source=GPS`、使用与 UMD982 实际输出一致的 NMEA 句子、`Require PPS Lock=ON`、GNSS 目的端口 `10110`。样件联调后以网页/API 读回值为准。

### 5.2 备选：PTP

XT32 支持 PTP：1588v2、802.1AS、802.1AS Automotive；可配置 UDP/IP 或 L2、Domain Number 0～127、锁定偏差上限 1～100 μs。PTP 模式下雷达不使用 PPS，也不发送 GNSS 数据包。

本项目暂不把 PTP 作为首版唯一同步链路，因为需要确认 Orin/交换设备是否有合格 PTP master、硬件时间戳和网络拓扑。若启用 PTP，必须单独验证主时钟、交换机、VLAN 和锁定/冻结状态。

## 6. 点云数据格式和记录要求

- 点云使用 UDP；默认源端口 10000、目的端口 2368；
- UDP 数据包固定以 `0xEE 0xFF` 开头，协议主版本 `0x06`、次版本 `0x01`；
- 通道数固定 32，数据块数 8，距离单位 4 mm，最多双回波；
- 每通道数据包含 Distance、Reflectivity 和保留字段；
- 尾部包含 Return Mode、Motor Speed、UTC Date & Time、UTC Fractional Seconds、Factory Information；
- 附加尾部有 4 字节 UDP Sequence，必须保存并检查丢包；
- 反射率默认线性映射，也可通过网页/PTC 改为非线性，任务配置要记录该设置；
- 准确垂直/水平角度应使用该台雷达的角度修正文件，不得只用设计角度表。

在 10 Hz 下，手册给出的点云传输率约为：单回波 22.52 Mbps，双回波 45.04 Mbps。Linux 采集预算应按双回波、协议/系统开销和并发下载留余量。

## 7. GNSS UDP 数据

GNSS 数据包包含 GNSS 时间、NMEA 数据、定位状态和 PPS 锁定标志。支持 GPRMC、GNRMC、GPGGA，数据多字节字段按小端传输；GPRMC/GNRMC 需要有效 UTC 时间和日期，GPGGA 需要 UTC 时间字段。

项目记录至少保存：

1. 点云 UDP Sequence、接收单调时刻和源 IP/端口；
2. 点云包 Date & Time、UTC Fractional Seconds、Motor Speed、Return Mode；
3. GNSS 数据包、NMEA 原文、GNSS Positioning Status、PPS Lock Flag；
4. 雷达的时间源、PPS/NMEA/PTP 状态和配置快照；
5. 对应角度修正文件、雷达序列号、固件版本和任务 ID。

## 9. 尚需补充的资料和验证

- 确认实际是 100BASE-TX 还是 100BASE-T1、侧面出线还是底部出线；
- 确认设备序列号、固件版本、角度修正文件是否与当前雷达匹配；
- 用 UMD982 样件确认 NMEA 句子、RS232 电平、波特率和 PPS 分配；
- 在 Orin NX 上验证百兆网口、VLAN、防火墙、UDP 接收缓冲和双回波峰值带宽；
- 验证掉包、断网、重连、GNSS 失锁、PPS 失锁、PTP 冻结和雷达重启；
- 获取适用于当前 XT32 固件的 PTC/HTTP/API 文档，决定 Linux 是否直接使用 API 控制参数；
- 现场标定安装姿态、雷达坐标系、角度修正文件和车体坐标系关系。
