## 2. 三端接口归属

### 2.1 PCB 到传感器和主机

| 链路 | 方向 | 责任端 | 当前接口假设 | 必须验证 |
|---|---|---|---|---|
| IMU 数据 | ADIS16477 → PCB | PCB | SPI + DRDY | SPI 读取截止时间、DRDY 抖动、DMA/中断、缓存溢出策略 |
| 绝对时间 | UMD982 PPS → PCB | PCB | PPS 输入；秒号通过 UMD982 数据或主机协议关联 | PPS 电平、边沿、线缆延时、秒号映射和失锁状态 |
| 相机触发 | PCB → 相机 | PCB | 硬件触发输出；电平和数量待定 | 触发电平、脉宽、频率、四路同步和异常安全状态 |
| 主机控制 | Linux ↔ PCB | Linux/PCB | 串口、USB 或以太网待定 | 物理接口、波特率/速率、帧错误、升级和掉电握手 |
| 电源控制 | PCB ↔ 电源/BMS | PCB | GPIO/ADC/继电器或电源管理器件待定 | 过压/欠压/过流、掉电通知、延时、复位和看门狗 |

### 2.2 Linux 设备与存储

| 设备 | Linux 连接方向 | 软件归属 | 冻结规则 |
|---|---|---|---|
| UMD982 | 数据口由 Linux 独占；RTCM 写入同一 GNSS 服务 | GNSS 服务 | 禁止多个进程同时写串口；保存原始输出、接收时刻和质量状态；UART/PPS/RESET_N 接线以 UMD982 配置提取为依据 |
| XT32 | 以太网接入 | 雷达适配器 | 以正式协议和 SDK 为准；时间同步方式单独验收 |
| 海康相机 ×4 | USB3.0；具体载板端口拓扑待确认 | 相机适配器 | `MV-CS050-80UM/UC` 标称 2448×2048、最高 80 fps；必须先冻结 USB3 主控/扩展、帧率、ROI 和触发线 |
| 合宙 Cat4 | USB 网络、串口或载板接口待确认 | Linux 4G/NTRIP | Linux 管拨号、NTRIP、重连；PCB 只管供电和必要复位 |
| SSD/HDD | NVMe/SATA/USB/转接待确认 | 记录服务 | 原始记录与算法成果分区；采集中禁止覆盖未完成任务 |
| Surface | 局域网访问 Linux | Windows 客户端 | 任务列表、分段下载、断点续传和摘要校验，不直接访问设备路径 |

## 3. 数据、带宽和功耗预算

### 3.1 计算方法

在相机、雷达和存储型号冻结前，不填写宣传参数作为预算结论。以实测或正式数据手册中的峰值为输入：

```text
B_data = B_xt32 + 4 × B_camera + B_imu + B_gnss + B_control
B_disk = B_data × (1 + protocol_overhead) × (1 + safety_margin)
P_system = P_pcb + P_xt32 + 4 × P_camera + P_orin + P_storage + P_cat4 + P_margin
```

其中 `protocol_overhead` 和 `safety_margin` 在样件验证记录中填写；不能把 GPU TOPS 或模组标称功率当作整机采集带宽或整机功耗。

### 3.2 预算冻结门槛

| 项目 | 冻结门槛 | 证据 |
|---|---|---|
| 采集入口带宽 | 所有设备峰值加协议开销后，仍低于实际端口和交换设备的持续能力，并保留并发余量 | 端口拓扑、抓包统计、连续采集日志 |
| 磁盘写入 | 目标存储持续写入能力高于最坏采集速率，并在满负载时记录无静默覆盖 | `task0_storage_benchmark.csv`、掉盘/满盘测试 |
| 局域网下载 | 下载限速后不能影响采集写入和关键控制；下载支持分段、摘要和断点 | 下载压测与采集并发日志 |
| 供电连续能力 | DC-DC/电源连续能力不低于实测峰值的 1.3 倍，瞬态能力另按启动和雷达/硬盘峰值验证 | 电源示波器、电子负载记录 |
| 散热 | 采集、写盘和网络并发时，所有器件在目标环境温度下不触发降频或保护 | 温度曲线、JetPack/驱动版本、环境条件 |
| 任务容量 | 根据有效写入速率和可用空间计算连续采集时长，系统盘、预留空间和故障分区单独扣除 | 容量计算表和实测任务目录 |

## 4. 当前明确的连接决策

1. IMU 优先由自研 PCB 采集；Linux 保存带源时间戳、序号、启动编号和同步质量的数据。
2. UMD982 数据口由 Linux 独占管理；PPS 送入 PCB 同步电路；双天线航向和定位质量随 GNSS 原始数据保存。
3. 合宙 Cat4 接 Linux，由 Linux 运行 NTRIP 并向 UMD982 转发 RTCM；PCB 管供电、硬件复位和掉电配合。
4. Linux 负责原始采集、任务存储、参数服务、诊断和局域网下载；在线轨迹解算、AI 识别和 AI 告警不纳入 Linux 验收。
5. Windows Surface 负责深度参数设置、下载、回放、标定、轨迹解算、点云、AI 和跨次变化分析。
