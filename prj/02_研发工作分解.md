# 研发工作分解

> 后续边界更新见 [三端工作边界与接口决策](03_三端工作边界与接口决策.md)。W10、W12、W13 的解算与分析归 Windows；原 W14“边缘推理”不属于当前 Linux 工作范围，调整为 Windows 推理与批处理部署。原在线推理及告警延迟指标不再作为 Linux 验收项。Windows 增加深度参数配置；Linux 增加 RTCM 差分链路，具体 4G 接入位置待定。

整理日期：2026-09-30。本文件把 V6 规划拆成可交付、可验证的工作包。原方案选型作为起点；新增工程任务是本次整理建议，完成情况均待项目实际资料确认。

## 1. 产品交付边界

应交付一套能够安装、运行、录制、回放、定位异常并维护的完整设备，包含硬件、固件、算法、上位机、数据、安装与测试资料。

三条业务链路分别定义：

1. **巡检采集**：多传感器同步 → 定位/建图 → 原始数据记录与回放。
2. **当次异常识别**：图像/点云分析 → 异物或施工目标 → 空间位置与告警证据。
3. **环境变化识别**：历史基准与当次数据 → 同一路段匹配和配准 → 变化候选 → 筛选、定位与人工复核。

第三条不能仅以相邻图像差异替代；应先定义业务上需要比较的时间跨度、区域、变化类别和最小变化规模。

## 2. 需求与验收先行

以下条件应在研发启动阶段形成书面需求：

| 主题 | 需确定的内容 | 对研发的影响 |
|---|---|---|
| 巡检条件 | 车速范围、线路、安装高度、横向检测距离、最小目标 | 决定分辨率、曝光、帧率、雷达布置与算法范围 |
| 环境范围 | 白天/夜间、雨雾程度、隧道、遮挡和 GNSS 中断 | 决定数据覆盖、照明、融合与降级策略 |
| 安装供电 | 安装空间、载荷、线缆走向、车辆电源和操作终端 | 决定结构、供电和接口拓扑 |
| 数据结果 | 录制时长、原始/压缩格式、轨迹、图像、点云及导出格式 | 决定存储、带宽、回放和数据管理 |
| 告警业务 | 类别、分级、保护区定义、去重、确认、定位和证据 | 决定告警规则、界面和评价方式 |
| 验收方法 | 数据集拆分、场景覆盖、测量方法、误报分母、责任方 | 使性能目标能被重复验证 |

原文的“距离轨道中心 ≤10m”“前后帧差异 ≥30%”暂作为待确认规则，不直接固化为业务验收标准。

## 4. 关键研发链路与依赖

### 4.1 先形成稳定的数据底座

W01 接手 → W02 需求 → W03 接口验证 → W04/W05 同步板与固件 → W07 驱动 → W08 录制回放 → W09 标定。

判断标准是“数据可持续记录、时刻一致、空间关系正确、能够离线复现”。仅出现图像或点云窗口，不代表此链路完成。

### 4.2 算法在可复现数据上迭代

W09 标定＋W08 数据 → W10 定位建图；W11 数据集 → W12 目标识别；W10/W11 及历史基准 → W13 变化检测。

W11 的类别定义和标注流程可以提前开展；正式性能评估必须使用独立测试集。3000 张或 5000 张是原规划的数据规模，不能据此保证达到精度目标。

### 4.3 软件与整机逐步收敛

W15 上位机可先基于固定消息协议和回放数据开发；W14 部署与 W06 散热需要联动验证。最后通过 W16 整机测试确认四路采集、SLAM、AI、录制和界面同时运行时的实际能力。

沿用原规划的日历锚点，使用新的 G 编号，避免继续沿用原文不一致的 A 编号。

## 6. 性能目标与验证工作

下列数值沿用 V6 目标，尚未证明可达。测试前需确定仪器、数据集、工况、统计方法和通过阈值。

| 验收项 | 原规划目标 | 必须补齐的验证定义 |
|---|---|---|
| 时间同步 | ≤1ms | 比较哪些传感器、时间戳代表采样还是接收、最大值/分位值、失锁处理 |
| RTK 定位 | 水平≤2cm、高程≤5cm | 静态/动态、参考真值、差分条件；与最终异常地理定位误差分开验收 |
| AI 检测 | 综合 mAP@0.5≥0.75，召回率≥0.80 | 类别、目标尺寸、场景分层、样本独立性和各类最低要求 |
| 推理 | 单帧≤30ms | 模型规模、输入尺寸、精度模式、单路/四路、是否包含预后处理 |
| 告警 | 延迟≤500ms，误报率≤5% | 起止时间、排队和界面延迟；误报按帧/事件/小时/里程的哪种分母统计 |
| 环境变化 | 原文只有变化规则，缺少完整验收指标 | 明确变化类型、空间范围、跨次间隔、变化检测精度及复核流程 |
| 连续录制 | ≥8h | 四路图像帧率/编码、点云/IMU 频率、实际写入速率、允许丢帧和恢复方式 |
| 供电 | 整机≤80W，备用续航≥1h | 满负荷测量、峰值功耗、温度、电池状态及切换期间数据完整性 |
| 结构环境 | ≤15kg、IP65、-20～60℃ | 是否含支架/电池；温度运行负载、防护测试条件；振动要求需另行明确 |
| 可靠性 | 原文未给出完整指标 | 启动失败、传感器中断、磁盘满、进程退出、掉电和重启的恢复要求 |

## 7. 团队工作边界

| 角色 | 主责 | 必须明确的协作边界 |
|---|---|---|
| 技术负责人 | 需求、架构、硬件/结构、标定与融合技术把关、供应商及现场协调 | 指定算法负责人；决定模型、算力、功耗和成本之间的取舍 |
| 嵌入式工程师 | STM32 固件、Jetson 系统、驱动、同步、ROS2 和部署 | 与负责人分工定位融合；与 PC 端共同冻结消息及文件协议 |
| PC 端工程师 | Qt、数据展示、回放、告警交互及导出 | 不默认同时包揽模型训练、全部 SLAM 和固件；算法职责需要单独排工时 |
| 测试工程师 | 用例、采集、标注质量、回归和现场证据 | 专项环境试验可能需要外部资源；标注外包与内部标注避免重复预算 |

原规划没有独立 AI 岗位。应明确训练、变化检测和性能评估由谁承担；如现有人力不足，再选择缩减首版范围、增加外部支持或调整进度，并同步核算预算。

## 9. 最终交付包

1. **硬件包**：最终 BOM、原理图/PCB、加工及安装图、线束、装配和出厂测试资料。
2. **软件包**：固件、驱动、算法及上位机源码，固定依赖、构建脚本、镜像、安装包和回滚方法。
3. **算法数据包**：模型、训练配置、数据集索引、标注规范、标定文件和性能评价报告。
4. **测试包**：需求与用例映射、实验室及现场报告、缺陷关闭记录和原始证据。
5. **使用维护包**：操作说明、告警解释、数据导出、维护校准、常见故障和备件说明。
