## 1. 硬件组成与边界

硬件分为感知、计算存储、同步采集、电源、结构散热和连接六部分。研发还需要调试仪器、标定工具、训练与备份资源。

设备与车辆的边界必须先确定：传感器和计算机分别放在车顶还是车内、车辆提供何种电源、线束如何穿舱、人员如何操作、是否需要移动网络。上述条件会影响结构、接口、功耗和成本。

### 3.1 不能省略的接口核对

- 双网口是否足够，取决于四路相机使用 GigE 还是 USB，以及雷达和外部通信占用；不能从“有两个网口”直接推导“不需要扩展”。
- 工业相机要同时确定镜头、视场、安装朝向、触发和曝光策略；夜间若需照明，应作为条件采购项单独核算。
- IMU 原始数据、硬件时刻与主机接收时刻应有明确传递路径；不能只连接 PPS 而不设计数据时间戳。
- SSD、HDD 的接口数量、转接、电源和机械固定要落到具体载板和安装图。
- PPS 与 PTP 的实现职责、支持器件及失锁行为需要分别设计，不能以“支持同步”代替接口证明。

## 4. 原预算未明确覆盖的项目

下表是需要核查的缺口，不代表全部必须新增采购。已有设备或供应商套装可覆盖的，应记录证据并避免重复计费。

| 项目 | 是否必需 | 处理方式 |
|---|---|---|
| 4 路相机镜头、防护窗及遮光结构 | 成像链路必需 | 查清是否随相机/机箱提供，补齐焦距和视场设计 |
| GNSS 模组底板、线缆和供电配套 | 取决于购买形态 | 区分裸模组、开发板与工业成品接收机 |
| RTK 差分来源 | 若按 RTK 精度验收则必需 | 明确网络差分或自建基站，以及网络、账号或服务费用 |
| 网络交换机 / USB 或存储扩展 | 条件必需 | 接口资源与带宽核算后决定 |
| 主电源、充电器及电池切换配套 | 供电链路必需 | 与车辆供电方案一起核对，不默认 400 元已经覆盖 |
| Windows 操作与后处理终端 | Surface 平板 | Qt 运行于 Surface；型号、CPU 架构、内存、磁盘、局域网接入及配件另行确认和计价 |

| 夜间补光 | 取决于成像实测和场景范围 | 先验证现有图像质量，再确定功耗、光学和安装要求 |
| 防水呼吸、接地及维护附件 | 依据结构环境设计 | 核查是否计入结构配件预算 |
| 标定工具、治具、研发备份存储 | 研发必需 | 优先盘点现有资产；未覆盖的计入研发配套预算 |

## 6. 采购批次和数量核对

建议分批锁定，而不是在接口未验证前购买完整双套：

1. **接口验证批**：先盘点可接手资产，取得一套计算平台、雷达、IMU、定位组件及单路候选相机，用于驱动、授时和接口验证。
2. **整机样机批**：相机扩展到四路；采购同步板、供电、完整存储、机箱和线束，完成持续采集和整机热测试。
3. **备件与迭代批**：依据故障影响及供货周期补齐第二套关键件，按试验反馈启动后续外壳版本。
4. **验收冻结批**：冻结型号、固件、线束及加工图，形成最终 BOM 和替代料规则。

## 7. 硬件冻结的交付清单

- 带准确型号、数量、供应商、报价日期、交期及替代料的 BOM。
- 接口资源表、数据带宽表、供电树和整机功耗表。
- 原理图、PCB、固件烧录资料、测试点及板级测试报告。
- 结构三维模型、二维加工图、安装图、线束图和装配工艺。
- 标定文件及对应的设备编号、安装版本和日期。
- 样机连续采集、同步、掉电、温升、振动及防护测试记录。
